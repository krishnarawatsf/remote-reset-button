1) Problem to Business Value

Before Automation

  • Camera freezes at remote shop.
  • Engineer drives to site.
  • Manual unplug and replug.
  • High time and travel cost.

After Automation

  • Find interface by description.
  • PATCH port down then up.
  • Recover service from desk.
  • Consistent, auditable process.
Speak track: explain pain first (travel, downtime), then business value (fast recovery, repeatability).

3) Execution Phases

Find which interface owns a device by name or description.

python3 find_device.py "Camera 2"
  • Calls GET on interface collection.
  • Matches on name and description.
  • Returns interface and status.

Power-cycle a port remotely with safe partial updates.

python3 reboot_port.py GigabitEthernet2
  • PATCH enabled=false
  • Wait reboot interval
  • PATCH enabled=true

Run complete scenario in one command.

python3 demo.py
  • Starts mock server.
  • Runs search and reboot phases.
  • Prints summary suitable for demo day.
Speak track: phase 1 identifies the correct port, phase 2 safely reboots, phase 3 is demo automation.

4) Technical Proof Points

Headers

Accept: application/yang-data+json
Content-Type: application/yang-data+json

YANG Wrapper

{
  "ietf-interfaces:interface": {
    "name": "GigabitEthernet2",
    "enabled": false
  }
}

Status Codes

  • GET -> 200
  • PATCH -> 204
  • Auth fail -> 401
  • Missing interface -> 404

Verification Command

./tools/verify.sh

Runs smoke checks and exits non-zero if something fails.

Speak track: highlight standards compliance (media type, wrapper, codes) to show engineering correctness.
